# Безопасность ByPass

В ByPass 0.5.0 обновления оболочки проверяются по подписи RSA-3072/SHA-256. Открытый ключ встроен в программу, закрытый ключ хранится отдельно от репозитория и GitHub Actions. Проверяются подписанные адрес, версия, размер и SHA-256 архива, а затем хеши EXE и config. Неподписанные метаданные и подменённые файлы не устанавливаются. Версии ниже установленной не предлагаются.

Для ядра встроен подписанный каталог проверенного выпуска **Flowseal 1.10.3**. Перед запуском проверяются EXE, DLL, драйверы, стратегии и остальные неизменяемые файлы. Посторонние файлы и ссылки на другие папки отклоняются. Пользовательские списки, игровые порты и предусмотренные файлы ACTIVE остаются изменяемыми. Новое ядро допускается только после проверки и включения его каталога в новый выпуск оболочки; одного хеша из GitHub недостаточно.

При обычном запуске окно работает с правами пользователя. Запрос Windows появляется при запуске отдельного `ByPass.EngineHost.exe`. Он читает файлы с правами пользователя, копирует разрешённые компоненты в папку `%ProgramData%\ByPass`, доступную для записи только администраторам и SYSTEM, повторно проверяет их и запускает ядро оттуда. Команды управления передаются через локальный именованный канал с проверкой процессов и ограничением размера. Доступ к каналу из сети запрещён. При закрытии окна, разрыве связи или завершении помощника его ядро останавливается через Job Object. Чужие процессы winws не завершаются. Не запускайте окно вручную «от имени администратора»: оно наследует права запустившего его процесса.

Готовый выпуск сканируется Microsoft Defender без исключений и без отключения защиты. Результат, время, версия баз и хеши архивов опубликованы в `security-report.json`; хеш отчёта входит в подписанный `update.json`. Обнаружение угрозы или невозможность сканирования блокирует выпуск. Чистый результат отражает проверку конкретных файлов конкретными базами, а не обещание отсутствия любых уязвимостей или срабатываний других антивирусов.

## Что ещё требуется

- **Доверенный сертификат Windows отсутствует.** Подпись обновления защищает механизм обновления, но не создаёт проверенного издателя в Windows. EXE пока `NotSigned`, SmartScreen может показать предупреждение. Поддержка настоящего сертификата подготовлена в `tools/sign-executable.ps1`; самоподписанный сертификат не используется.
- Первая установка и переход с версий до 0.5.0 начинают скачивание через прежний механизм доверия. В 0.5.1 новый помощник дополнительно получает подписанные данные именно своей версии и проверяет их перед установкой; подделанные старые хеши не принимаются. Защита проверок скачивания работает после установки нового приложения. Если старое ядро 1.10.2 не проходит проверку, распакуйте новый полный ZIP и перенесите свои пользовательские списки через вкладку «Дополнительно».
- Защита не рассчитана на заражённую Windows, злоумышленника с правами администратора или замену самого EXE при первой установке. Подпись каталога удостоверяет одобренные байты, но не исправляет возможные ошибки в zapret/WinDivert. ByPass не скрывает IP и не шифрует весь трафик.
- Закрытый ключ защищён DPAPI текущей учётной записи и ACL, но доступное этой учётной записи вредоносное ПО может попытаться использовать ключ. Компьютер выпуска и GitHub-аккаунт требуют защиты: включите 2FA/passkey и сохраните коды восстановления. Настройки личного аккаунта программа не меняет.

## Для владельца релиза

Закрытый ключ создан в `%LOCALAPPDATA%\ByPass\Signing\release.key`. В Git хранится только открытый ключ и подписанный каталог. Не добавляйте закрытый ключ в Git, Actions secrets, ZIP или сообщения. `initialize-signing.ps1` не перезаписывает существующие ключи. Смена открытого ключа требует отдельного миграционного релиза, подписанного прежним ключом; простой замены файла недостаточно для установленных клиентов.

DPAPI-файл привязан к текущей Windows-учётной записи: копирование его на другой компьютер не даёт рабочей резервной копии. Для второго компьютера и резервирования используйте `tools/export-signing-key.ps1` и `tools/import-signing-key.ps1`: ключ переносится в зашифрованном файле с отдельным паролем, введённым только локально. При импорте проверяется тот же открытый ключ и создаётся DPAPI-копия под второй учётной записью. Инструкция есть в DEVELOPMENT.md. Не удаляйте текущий профиль или ключ до подготовки такой копии. При потере ключа существующие клиенты не примут новые подписи; потребуется ручная переустановка.

Для будущих опубликованных релизов включена защита GitHub Immutable Releases: файлы и тег после публикации нельзя заменить. Actions собирает и сканирует **черновик**, не получает закрытый ключ и не публикует его автоматически. Владелец локально проверяет чистый commit, собирает пакет, сканирует, подписывает и публикует через `tools/publish-release.ps1`. Скрипт требует успешный workflow именно этого commit и не перезаписывает публичные релизы. Инструкция — [DEVELOPMENT.md](DEVELOPMENT.md).

Если антивирус сообщает об угрозе, сохраните название обнаружения и хеш файла, остановите использование и сообщите через [Issues](https://github.com/xxXdemidXxx/discord_obhod_app/issues). Не отключайте защиту и не добавляйте всю папку в исключения. Для проверки ложного срабатывания можно отправить файл через [официальную форму Microsoft](https://www.microsoft.com/en-us/wdsi/filesubmission).
