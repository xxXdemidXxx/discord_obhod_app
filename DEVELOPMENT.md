# Разработка и публикация

[На главную](README.md) · [Инструкция пользователя](USAGE.md)

ByPass написан на C# / WinForms для Windows 10/11 x64 и .NET Framework 4.8. NuGet не используется; сборка выполняется системным компилятором .NET Framework.

## Сборка и проверка

Запускайте PowerShell из корня репозитория:

```powershell
./fetch-engine.ps1
./build.ps1
./test.ps1
./package-friends.ps1
```

- `fetch-engine.ps1` скачивает официальное ядро 1.10.3 и проверяет закреплённый SHA-256.
- `build.ps1` создаёт `dist/ByPass-<версия>.exe` и config, а также совместимую копию `Obhod-<версия>.exe`. Для запуска нужна папка `data` с ядром и настройками.
- `test.ps1` проверяет приложение без запуска настоящего драйвера. Сам скрипт при необходимости скачивает архив ядра. С `-Network` дополнительно выполняются реальные GitHub и HTTPS-запросы.
- `package-friends.ps1` создаёт готовый архив с EXE, config, стандартными настройками, официальным ядром, инструкцией и лицензиями. Исходники оболочки, тесты, скрипты сборки, личные списки и журналы в него не попадают. BAT-файлы и утилиты из официального ядра сохраняются: оболочка читает стратегии из BAT как данные.
- `prepare.ps1` импортирует локальное ядро 1.10.2 и официальное 1.10.3 для разработки, сохраняя настройки. Путь локального ядра можно передать параметром `-LocalEngine`.

Тесты охватывают разбор стратегий, Windows-кавычки, владение процессом, ZIP traversal, сохранение/откат, полный автоподбор, подтверждение победителя, отмену, DNS/TLS, метаданные релизов и замену EXE. Снимки окна сохраняются в `tests/window*.png`.

## Файлы релиза

| Файл | Назначение |
| --- | --- |
| `ByPass-win-x64.zip` | Готовая программа по постоянной ссылке для пользователей |
| `ByPass-win-x64.zip.sha256.txt` | SHA-256 пользовательского архива |
| `Obhod-<версия>-win-x64.zip` | Совместимый пакет для обновляторов старых версий |
| `Obhod-<версия>-win-x64.zip.sha256.txt` | SHA-256 архива |
| `update.json` | Метаданные для проверки обновлений приложения |

Пользовательский архив содержит папку `ByPass` и `ByPass.exe`. Совместимый архив сохраняет расположение `Obhod/Obhod.exe`, которое требуют старые обновляторы. EXE и config в обоих архивах побайтово одинаковы; пути внутри ZIP отличаются, поэтому SHA-256 архивов различается.

Внутреннее имя .NET-сборки `Obhod-<версия>`, пространство имён и mutex сохраняются для совместимости. Название продукта Windows, окно, трей и новый ярлык используют ByPass. Обновление заменяет EXE по прежнему пути: у старой установки имя файла может остаться Obhod.exe, а интерфейс станет ByPass.

Постоянная ссылка для README и распространения:

```text
https://github.com/xxXdemidXxx/discord_obhod_app/releases/latest/download/ByPass-win-x64.zip
```

`update.json` продолжает ссылаться на архив с номером версии: установленные версии 0.3/0.4 принимают только такое имя. Новый обновлятор принимает оба имени, проверяя точный адрес репозитория и тега, размер, SHA-256 и версию EXE. Не удаляйте архив с номером версии, пока нужна совместимость со старыми приложениями.

Подпись издателя отсутствует; SHA-256 удостоверяет соответствие опубликованному архиву. Заменяются только EXE и config; пользовательские данные и версии ядра остаются на месте.

## Публикация новой версии

1. Увеличьте `AppVersion.Value` в `src/Version.cs`, например до `0.4.4.0`. Обновите версии в документации и `RELEASE-NOTES.md`.
2. Выполните локальные проверки, сделайте commit и push в `main`.
3. Workflow `Build, test and release` соберёт и проверит приложение, создаст тег `v<версия>` и опубликует релиз.
4. Постоянная ссылка начнёт скачивать новый архив. Установленные приложения получат релиз при следующей проверке обновлений.

Повторный push с прежним номером не перезаписывает опубликованный релиз; для обновления нужен новый номер. Pull request собирается и проверяется без публикации. GitHub Actions должен быть разрешён в настройках репозитория. Используется `GITHUB_TOKEN` workflow; отдельные токены для сборки не нужны.

Постоянная ссылка становится доступной после первой публикации релиза с `ByPass-win-x64.zip`. Старые релизы содержат только архивы с номером версии.

При запуске выполняется только проверка обновлений. Уведомления оболочки и ядра отображаются в окне на всех вкладках и могут быть скрыты до следующего запуска. Скачивание начинается после нажатия «Обновить» и отдельного подтверждения «Да / Нет» с выбором «Нет» по умолчанию. Обновление ядра требует остановить обход; обновление оболочки восстанавливает подключение после перезапуска.
