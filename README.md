# Обход

Приложение для Windows 10/11 x64 с окном управления Flowseal zapret-discord-youtube. Это самостоятельная оболочка, не официальный продукт Flowseal. Версия оболочки **0.3.0**, включённое ядро **1.10.3**. Нужен .NET Framework 4.8.

**[Скачать последнюю версию](https://github.com/xxXdemidXxx/discord_obhod_app/releases/latest)** · [Инструкция для тестирования](TESTING-GUIDE.txt)

## Запуск

1. Скачайте ZIP из Releases и распакуйте всю папку `Obhod` в постоянное место. Из архива приложение не запускайте.
2. Откройте `Obhod.exe`. В «Помощь» можно создать ярлык на рабочем столе.
3. Нажмите **«Автоподбор всех стратегий»** или выберите стратегию и **«Применить и проверить»**. Запуск драйвера требует подтверждения UAC.
4. Результаты YouTube, Discord и GitHub видны рядом со стратегией. При смене стратегии приложение само остановит своё ядро, запустит новое и повторит проверки.
5. Крестик скрывает окно в трей. Для завершения выберите «Выход» у значка: остановится только собственный процесс ядра.

Ядро запускается без консольного окна. Всплывающих уведомлений оболочка не отправляет. Системный запрос UAC остаётся необходимым для WinDivert. Если работает другой winws или служба zapret, сначала остановите их в исходном приложении: оболочка не завершает чужие процессы.

## Автоподбор и диагностика

Автоподбор последовательно проверяет все стратегии текущего ядра, показывает результаты в таблице, затем повторно проверяет варианты с 5/5 по возрастанию средней задержки. Первый подтверждённый вариант сохраняется и остаётся включённым. Если подходящего нет или нажата «Отмена», возвращается предыдущее состояние подключения. Кнопка «Остановить подбор» выключает обход. Двойной щелчок по строке истории выбирает стратегию для ручной проверки.

Пять проверок выполняются параллельно прямыми HTTPS-запросами без системного HTTP-прокси: сайт YouTube, изображение i.ytimg.com, сайт Discord, Discord API и GitHub API. Тайм-аут — 12 секунд. При смене подключения старые результаты сбрасываются. Эти проверки не подтверждают воспроизведение видео, вход в аккаунт и голосовой UDP: проверьте ролик и голосовой канал отдельно.

Ошибка **DNS** означает, что Windows не определила имя. «Диагностика DNS» сравнивает Windows DNS с Google DNS через HTTPS и показывает текущие DNS-серверы. Системные настройки автоматически не меняются. У браузера может быть отдельный Secure DNS. [Инструкция Google для Windows](https://developers.google.com/speed/public-dns/docs/using#windows).

## Настройки и ядро

GameFilter и диапазоны TCP/UDP находятся в «Настройки» и меняются при выключенном обходе. Пользовательские домены: `list-general-user.txt`, исключения: `list-exclude-user.txt`, IP-исключения: `ipset-exclude-user.txt` в списках текущего ядра.

Стратегии читаются как данные; BAT не исполняются. Параметры передаются непосредственно winws. Для стратегий с `dpi-desync-fooling=ts` включаются TCP timestamps, как в исходном service.bat; это записывается в журнал. Остальные стратегии эту настройку не меняют.

Ядро обновляется отдельной кнопкой из [официальных релизов Flowseal](https://github.com/Flowseal/zapret-discord-youtube/releases/latest). Проверяются URL, размер и SHA-256 GitHub. Распаковка запрещает выход за каталог и символьные ссылки; проверяются файлы и стратегии. Пользовательские списки, GameFilter, изменённый IPSet и активные UDP-фейки сохраняются. Предыдущее ядро доступно для отката.

## Автоматические обновления приложения

Источник оболочки — **этот репозиторий**, стабильные GitHub Releases. Автообновления включены по умолчанию; отключаются в «Обновления». Проверка выполняется при открытии и каждые **15 минут**, пока приложение работает. Это периодический опрос, не мгновенные push-уведомления.

Новая сборка скачивается и проверяется по SHA-256 GitHub, версии EXE и фиксированному URL репозитория. При выключенном обходе и отсутствии других операций оболочка сама обновится и перезапустится. При активном обходе сборка ждёт остановки; кнопка «Обновить оболочку» позволяет обновиться сразу и восстановить подключение. Заменяются EXE и его config; `data`, настройки, списки и версии ядра не перезаписываются. Предыдущий EXE остаётся в `.previous`. При ошибке замены восстанавливается старый EXE.

Старые 0.1/0.2 не умеют обновлять оболочку: один раз установите 0.3.0 вручную. Подпись издателя отсутствует; проверка SHA-256 удостоверяет соответствие опубликованному GitHub-архиву.

## Разработка и публикация

Без NuGet; сборка системным компилятором .NET Framework:

```powershell
./fetch-engine.ps1
./build.ps1
./test.ps1
./package-friends.ps1
```

`build.ps1` создаёт `dist/Obhod-0.3.0.exe`. `package-friends.ps1` создаёт чистый `releases/Obhod-0.3.0-win-x64.zip`, внутри стабильное имя `Obhod.exe`, стандартные настройки и проверенное официальное ядро. Личные списки и журналы не попадают в архив. `prepare.ps1` сохраняет локальные настройки и импортирует ядра для разработки.

Проверки охватывают разбор стратегий, Windows-кавычки, владение процессом, ZIP traversal, сохранение/откат, полный автоподбор, повторную проверку победителя, отмену, классификацию DNS/TLS и проверку метаданных релизов. Настоящий драйвер в тестах не запускается. С `./test.ps1 -Network` дополнительно проверяются реальные GitHub и HTTPS-запросы. Снимки окна сохраняются в `tests/window*.png`.

**Для новой версии:**

1. Увеличьте `AppVersion.Value` в `src/Version.cs`, например до `0.3.1.0`. Обновите `RELEASE-NOTES.md`.
2. Сделайте commit и push в `main`.
3. Workflow `Build, test and release` соберёт и проверит приложение, создаст тег `v0.3.1` и опубликует ZIP с SHA-256.
4. Установленные приложения получат новый релиз при следующей проверке. Повторный push с прежним номером не перезаписывает опубликованный релиз; для обновления нужен новый номер.

Pull request только собирается и проверяется, без публикации. GitHub Actions должен быть разрешён в настройках репозитория. Отдельные токены для сборки не нужны: используется ограниченный `GITHUB_TOKEN`.
