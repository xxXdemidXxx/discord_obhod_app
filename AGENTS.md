# Работа над ByPass

Пользователь предпочитает правки и выпуск обновлений через агента, без открытия помощника и ручного ввода команд. При поручении «сделай правки и выпусти / запушь обновление с билдом» доводи задачу до проверенного публичного подписанного релиза. Обычную просьбу только проверить код или изменить исходники не считай поручением публиковать релиз.

## Единый сценарий выпуска

1. Изучи нужный код, внеси правки и проверь diff. Получи актуальный `main`, учитывая локальные изменения; не сбрасывай чужую работу.
2. Выбери следующий свободный номер версии относительно опубликованного GitHub release. Обнови `src/Version.cs`, `README.md`, `TESTING-GUIDE.txt`, `RELEASE-NOTES.md`.
3. Из PowerShell 7 запусти `release.ps1` с сообщением commit и явным списком проверенных файлов:

```powershell
./release.ps1 -CommitMessage 'Release ByPass <версия>' -Files @('src/Version.cs','README.md','TESTING-GUIDE.txt','RELEASE-NOTES.md','<изменённые файлы>')
```

Для уже сохранённого чистого commit достаточно `./release.ps1`. Сценарий проверяет ключ и доступ к GitHub, запускает тесты, сохраняет выбранные изменения, пушит `main`, собирает пакет с подписью автора, сканирует Defender, подписывает метаданные, дожидается успешного Actions именно этого commit, публикует черновик и проверяет скачанные публичные файлы. Отдельное окно помощника не требуется.

Если песочница запрещает Git, сеть, DPAPI или проверку Defender, используй штатное согласование расширенных прав инструмента в рамках поручения пользователя. Отказ проверки нельзя обходить отключением защиты. Отсутствующий ключ на другом компьютере требует первоначального импорта пользователем; агент не может заменить этот шаг новым ключом. Выпуск выполняется на компьютере с локальным ключом под той Windows-учёткой, которая его создала или импортировала.

## Подписи и ограничения

- Закрытый ключ: `%LOCALAPPDATA%\ByPass\Signing\release.key`, DPAPI CurrentUser. Не создавай его повторно, не экспортируй автоматически, не читай/печатай содержимое, не отправляй в чат, Git, Actions или артефакты.
- Пароли резервной копии и сертификатов вводит только пользователь локально. Не проси прислать их агенту.
- Официальный SHA-256 открытого ключа: `813c22d95ae9b8e82d7776a5c8c87acb47c05bf3d0cfa6137ceeeb915b4e125f`. Не заменяй корень доверия ради успешного выпуска.
- При отсутствии `BYPASS_SIGNING_THUMBPRINT` работает собственная подпись ByPass, EXE остаётся без доверенной подписи издателя Windows. Не называй её Authenticode и не обещай отсутствие SmartScreen.
- Не пропускай тесты, Defender, проверку подписей или успешный Actions. Не публикуй чужой commit или изменённый после сборки checkout. Публичные релизы неизменяемы: исправления требуют новой версии.
- Не запускай настоящий драйвер и не подтверждай UAC автоматически ради автотеста. Сообщай о пределах такой проверки.
- Пользовательский ZIP содержит готовую программу, ядро и руководство; инструменты владельца, исходники, ключи и тесты в него не добавляй.
- GUI `owner.cmd` остаётся необязательным способом резервирования и переноса ключа. Инструкции: `OWNER-GUIDE.md`, `DEVELOPMENT.md`, `SECURITY.md`.

В финале укажи версию, ссылку скачивания/релиза, результат проверок и наличие подписи автора. При сбое сообщи конкретный незавершённый этап; не объявляй выпуск успешным до проверки опубликованных файлов.
