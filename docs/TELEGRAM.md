# Telegram в ByPass 0.6.0

В окне и трее два независимых переключателя: **Discord и YouTube** управляет основной стратегией, **Telegram (experimental)** — отдельным прозрачным TCP→WSS-мостом для Telegram Desktop. Настройка прокси в Telegram не требуется. Мост остаётся работающим при остановке, смене и автоподборе основной стратегии. Полный выход из ByPass останавливает мост; до входа пользователя в Windows он не работает. Звонки не поддерживаются.

«Частично · 2/5 DC» означает, что протокольную проверку прошли два дата-центра. Сообщения могут работать, часть подключений и вложений может быть недоступна. Подробности открываются по статусу. Эта диагностическая строка не влияет на выбор основной стратегии. При подборе Telegram проверяется один раз; результат сохраняется в таблице без переподключения моста.

## Реализация

Защищённый помощник принимает отдельные команды `telegram-start`/`telegram-stop` и сообщает отдельное состояние `telegram_running`. Для моста создаётся собственный проверенный снимок ядра. Команды основной стратегии не уничтожают его. Основная стратегия всегда оставляет Telegram TCP без desync, поэтому тумблер Telegram не требует перезапуска winws.

Отдельный WinDivert handle перенаправляет TCP 80/443/5222 опубликованных сетей Telegram в локальные listeners. DC/media определяются из заголовка транспортной обфускации; исходный зашифрованный MTProto-поток пересылается через официальный WSS endpoint. TLS-сертификат и WebSocket accept проверяются. Сокеты моста исключены из повторного перехвата. Не-MTProto соединения пересылаются напрямую.

Для DC2/DC4 первым используется альтернативный Telegram web endpoint 149.154.167.220, затем DNS-адреса. SNI/Host сохраняет имя соответствующего DC. Данные аккаунта и сообщения не расшифровываются, не читаются из файлов клиента и не сохраняются. DNS Windows, hosts, системный прокси и сертификаты не меняются.

Проверка — неавторизованный `req_pq_multi`/`resPQ` с проверкой nonce на пяти DC. Это проверка транспорта, а не отправка сообщения от аккаунта пользователя. Фоновый отказ WSS не останавливает основную стратегию. В журнал попадают только технические этапы, IP и счётчики байтов.

Источники: [Telegram transports](https://core.telegram.org/mtproto/transports), [официальные сети](https://core.telegram.org/resources/cidr.txt), [Telegram Desktop TCP](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/mtproto/connection_tcp.cpp), [альтернативный endpoint upstream](https://github.com/Flowseal/tg-ws-proxy/blob/main/proxy/config.py).
