# Telegram в ByPass

В окне и трее два независимых переключателя: **Discord и YouTube** управляет основной стратегией, **Telegram (experimental)** — отдельным прозрачным TCP→WSS-мостом для Telegram Desktop. Настройка прокси в Telegram не требуется. Мост остаётся работающим при остановке, смене и автоподборе основной стратегии. Полный выход из ByPass останавливает мост; до входа пользователя в Windows он не работает. Звонки не поддерживаются.

Начиная с 0.6.2 доступность отображается отдельно: `DC 2/5 · файлы 1/3`. Проверяются пять основных DC и три дополнительных транспорта: медиа DC2, медиа DC4, CDN203. Это протокольные пробы, которые не подтверждают загрузку файла из аккаунта. Подробности открываются по статусу. Диагностическая строка не влияет на выбор основной стратегии. При подборе Telegram проверяется один раз; результат сохраняется в таблице без переподключения моста.

В **Настройки → Медиа Telegram** есть **Резерв Flowseal / Cloudflare**. По умолчанию он выключен. После явного включения медиа DC2 и CDN203 используют внешние WSS-адреса из проверенного снимка upstream Flowseal. Для остальных DC резерв применяется при отказе штатного WSS. Оператор резервного маршрута видит IP и объём трафика; содержимое остаётся защищённым MTProto между Telegram Desktop и сервером Telegram. Включение настройки переподключает только Telegram. Изменения настроек Telegram не нужны.

## Реализация

Защищённый помощник принимает отдельные команды `telegram-start`/`telegram-stop` и сообщает отдельное состояние `telegram_running`. Для моста создаётся собственный проверенный снимок ядра. Команды основной стратегии не уничтожают его. Основная стратегия всегда оставляет Telegram TCP без desync, поэтому тумблер Telegram не требует перезапуска winws.

Отдельный WinDivert handle перенаправляет TCP 80/443/5222 опубликованных сетей Telegram в локальные listeners. DC/media определяются из заголовка транспортной обфускации; исходный зашифрованный MTProto-поток пересылается через официальный WSS endpoint. TLS-сертификат и WebSocket accept проверяются. Сокеты моста исключены из повторного перехвата. Не-MTProto соединения пересылаются напрямую.

Для сообщений DC2/DC4 сохранён быстрый альтернативный Telegram web endpoint 149.154.167.220. Для медиа DC2 без внешнего резерва сначала пробуются штатные DNS-адреса. CDN203 распознаётся отдельно и никогда не подменяется обычным DC2: у него другие ключи сервера. Без резерва CDN сохраняет исходный прямой TCP-маршрут. Данные аккаунта и сообщения не расшифровываются, не читаются из файлов клиента и не сохраняются. DNS Windows, hosts, системный прокси и сертификаты не меняются.

Проверка — неавторизованный `req_pq_multi`/`resPQ` с проверкой nonce. Фоновый отказ WSS не останавливает основную стратегию. Журнал ограничивает повторные события и раз в 30 секунд выводит изменившуюся сводку каналов, ошибок и объёма трафика. Нормальное закрытие и отмена не создают строку на каждое соединение.
